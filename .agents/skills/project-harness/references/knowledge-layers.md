# 知识分层

为 agent 准备的知识，按**触发时机**和**消费者**分层，而不是按内容主题。写规范、规则或 skill 前读这份。

---

## 三层结构

| 层 | 触发 | 适用内容 | 形态 |
|---|---|---|---|
| 规则 Rules | 常驻，进门即生效 | 不依赖当前任务的约束 | `AGENTS.md` 的硬约束段、`.cursor/rules`、lint/CI gate |
| 技能 Skills | 按需调用 | 有明确场景和完成定义的过程知识 | `SKILL.md` |
| 工作流 Workflows | 任务级编排 | 跨步骤的验证、监督、沉淀 | 检查脚本、监督角色、验收流程 |

判断标准很简单：

- **任何时候都该遵守** → 规则。
- **只有做某类事时才需要** → 技能。
- **要跨多个步骤编排** → 工作流。

---

## 规则层

### 特征

- 不需要"被叫到"就生效。
- 可以按路径/语言/目录作用域加载（改到某类文件才带对应规范）。
- 应放在最便宜、最自动的执行位置：能进 lint 就别写进文档，能进 CI 就别靠提醒。

### 写规则的要求

每条规则说清三件事：

1. **约束**：必须/禁止做什么。
2. **原因**：违反会导致什么具体后果。
3. **例外**：什么情况下不适用。

只说"要写单元测试"没有价值；要说"改动领域层必须补一条能红的检查，因为这类改动最容易在不报错的情况下改变行为"。

### 常见错误

- 把流程知识写成常驻规则，导致上下文常驻负担。
- 规则互相矛盾，agent 无法判断优先级。
- 规则太多，所有规则都变成噪声。

一个仓库的常驻规则控制在十几条量级。超过就说明该往技能层拆。

## 技能层

### 什么时候值得写成 skill

同时满足：

- 同类操作已出现**三次以上**。
- 步骤稳定，换执行者也能复现。
- 有明确的完成定义。
- 存在容易踩的坑或禁区。

不满足就不要写。一次性流程写成 skill 只会增加维护负担。

### 结构

```markdown
---
name: kebab-case-name
description: 做什么 + 什么时候用（触发信号写清楚，宁可写宽一点）
---

# 标题

## 何时使用 / 何时不用
## 流程（分步骤，含完成判据）
## 判定规则（决策表）
## 反模式
## 参考文件
```

### 质量判据

**过程稳，不是输出一致。** skill 不是提示词模板，不要求每次写出一样的字；它要求每次走的流程稳定、可预期。

一份合格的 skill：

- 触发条件是场景，不是关键词堆砌。
- 每步有可判断的完成标准。
- 明确写出禁区（绝对不做什么）。
- 解释为什么，而不只是命令。
- 长内容拆到 `references/`，主文件保持精简。

### 消费者决定门槛

| 消费者 | 错误后果 | 验收要求 |
|---|---|---|
| 同一团队的开发者 | 被 review 捕获 | 正常评审 |
| 下游 agent | 被放大成数据污染、错误决策 | 必须先验证，再交付 |

给下游 agent 用的工具或 skill，要求更硬：

1. 没读真实实现不要写。
2. 写了不验证不要交付。

因为这类错误不是"报个错就完了"，而是后面的执行者会拿着错的东西继续做。

## 工作流层

### 内容

- 验证流程（怎么触发、怎么判、证据在哪）。
- 大改动的分波监督。
- 验收结果的沉淀格式。
- 并行开发的并发约束。

### 并行约束

多个写者共享一套有状态环境时：

- 有状态服务视为独占资源，并行只在无状态部分（改代码）展开。
- 验证必须串行或隔离，不能各起一套。
- 分支动作推迟到提交时，因为只有那时才需要写者身份。提前 stash/checkout 会丢失更新。

这条规则常常与"工作区要一直干净"的直觉冲突。冲突时以不丢失他人工作为准。

---

## 升级与降级

### 规则 → 技能

当一条规则开始包含"先做什么、再做什么、做到哪算完"，它已经不是规则，应该拆成技能，规则里只留一句"做 X 时使用 skill Y"。

### 技能 → 工作流

当一个技能需要跨角色、跨会话编排（有人做、有人审、有状态要记录），升格为工作流，并配可命令检查的指标。

### 降级

- 三个月没人用的规则：删或合并。
- 没有触发过的技能：检查描述是否太窄，或场景根本不存在。
- 无判定的工作流：退回技能。

知识库的健康度不看条目数，看**被引用的次数**。

---

## 反模式

| 反模式 | 后果 | 修正 |
|---|---|---|
| 把所有内容塞进 `AGENTS.md` | 常驻上下文膨胀，重点被淹 | 拆到 skills/references |
| 规则只有禁令没有原因 | agent 无法在边界情况做判断 | 补原因和例外 |
| skill 写成提示词模板 | 每次输出不同、无法复现 | 改成流程 + 完成定义 |
| 为一次性场景写 skill | 维护负担 | 出现三次再写 |
| 技能描述过窄 | 该触发时不触发 | 写场景信号，不写精确关键词 |
| 下游工具未验证就交付 | 错误被放大 | 先验证再交付 |
| 两套入口文件并存 | 约定分叉 | 复用或迁移，不要并行 |
