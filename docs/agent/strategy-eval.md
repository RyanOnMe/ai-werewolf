# 策略提示词实测

## 对局

- 运行：`runs/strategy-12p`（gitignored）
- 板子：12 人预女猎白 + 上警
- 模型：`openai-codex/gpt-5.6-luna`，`--thinking medium`，`--max-tokens 3000`
- 结果：狼人胜，5 天，309 条事件，731.6 秒
- 用量：1,172,453 tokens（输入 586,336 / 输出 18,565；total 含缓存/推理）
- 异常：1 次 agent 超时 → 1 次保底发言（5 号警上发言等满 300 秒）；规则拒绝 0

复现：

```bash
npm run play -- --mode 12p \
  --model openai-codex/gpt-5.6-luna \
  --thinking medium --max-tokens 3000 --timeout 300 \
  --seed strategy-12p --out runs/strategy-12p
```

## 观察到的策略行为

### 1. 起跳不是复读：带查验、警徽流和归票

1 号预言家第一天警上直接报查验和警徽流：

> 我是1号真预言家，昨夜查验7号，结果是狼人，今天警长竞选的核心归票就是7号。……拿到警徽后，第一验优先验5号，验证对跳；若5号发言明显不像狼，则转验9号或12号这种警下关键位。警徽流暂留5、9，今天请警下集中投7号。

警下玩家没有无条件跟票，而是比较两个候选人的信息链：

> 1号的预言家状态和警徽流比较完整，尤其首验7号并明确给查杀，信息链是成立的。5号竞选发言基本没有验人和后续规划，可信度明显低于1号……7号需要正面解释自己与1号的对立。

### 2. 用票型和死亡顺序反推，而不是只看单次发言

第二天 1 号被刀、5 号被毒，警徽交给 2 号。6 号开始按“同质发言/跟票”拆狼坑：

> 昨夜1、5同时死亡，结合1号临终前明确要验5且把警徽交给2号，我倾向1号是真预言家，5号更像被验证/被处理的狼位……今天重点查狼应放在警下跟随最重、发言高度同质的8、9、10、11、12中，尤其9、10对1号和归票的论证几乎复读。

后续几天，玩家持续用“谁在什么轮次投了谁”来修正站边：

> 8号翻平民后，10号上一轮唯一投9，且今天继续把9锁成第一票位，这个连续行为确实像在制造8、9二选一并保留退路。

### 3. 警长/警徽进入叙事

警长不是 UI 上的一个标记，而是被玩家当作资源争夺和身份判断的一部分：

> 2号把警徽交给我，我会先按当前最集中、可复盘的线索归票。……今天我归票10号；若10出局后仍需继续查9，再结合11、12及其余警下位的站边复盘。

### 4. 狼人也能编造完整故事

狼人 4 号拿到警徽后，用“复盘票型”维持好人视角，连续带队推出 9、11；狼队最终屠民获胜。说明提示词不是只教好人背模板，而是让模型按阵营目标组织公开叙事。

## 仍然存在的问题

- **延迟/成本**：medium thinking 下这局 12 分钟、117 万 total tokens；其中一个警上发言等满 300 秒触发保底。低 thinking 更快，但策略密度通常会下降。
- **保底发言质量**：超时后的保底是“先听其他候选人”，信息量低；这是流程兜底，不是策略输出。
- **不能保证每局都精彩**：提示词提高了上限，但模型仍可能复读、误判或过度自信。需要用 `transcripts/seat-N.jsonl` 和事件流复盘。
- **没有自动策略评分**：目前只能人工看发言、票型和胜负，不能机器判定“这局打得聪明”。

## 结论

- 相比旧提示词，这局已经出现明确的自称/查杀/警徽流、对跳比较、票型联动、抗推和归票，不再是“我过/先听一圈”。
- 想稳定复现这种强度，建议 12 人局使用 `--thinking medium` 和支持较强推理的模型；成本敏感时用 `low`，并把 `view_strategy` 当作补救。
- 下一步可以加个人笔记工具、跨天摘要和自动策略评分，而不是继续堆更长的 prompt。
